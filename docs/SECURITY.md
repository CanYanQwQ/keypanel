# 客户端安全指南

## 凭据

`CARDKEY_APP_SECRET` 是高权限对称密钥，同时用于请求签名、响应验签和卡密传输加密。请使用环境变量、操作系统密钥链或云密钥管理服务注入；不要硬编码、打印或提交。

## TLS

生产环境必须使用 HTTPS，并启用证书验证。示例不提供关闭证书验证的生产路径。HMAC 和 AES-GCM 不能替代 TLS。

## 原始字节

请求签名必须覆盖最终发送的 raw body。响应验签必须覆盖实际收到的 raw body。不要先解析 JSON 再重新序列化计算摘要。

## Nonce 与重试

每次请求使用密码学安全随机 nonce；重试时重新生成 timestamp、nonce 和 signature。Nonce 不是业务请求 ID，也不是幂等键。

## 卡密传输加密

优先使用 HKDF-SHA256 + AES-256-GCM。IV 必须每次随机生成；AAD 必须为 AppID；Tag 校验失败必须拒绝。不要记录明文卡密、完整密文载荷或签名头。

## 浏览器前端

Vite 的 `VITE_*`、Vue/React bundle 和浏览器源码都是公开的。不要把 AppSecret 放进浏览器。浏览器示例只展示调用受保护后端代理的方式。

## 业务重试

`consume` 可能产生扣次副作用，网络超时后无法仅凭 `X-Request-Id` 去重。除非业务层另有幂等方案，不要自动重试未知结果的扣次请求。

## 日志

日志中只保留脱敏后的 AppID、请求结果和内部关联 ID；不要记录 AppSecret、完整卡密、完整请求体或完整响应体。
