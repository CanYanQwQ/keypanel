# 宝塔面板部署指南

本文档针对**宝塔面板（Linux）**的部署流程，逐步说明每一步的操作与原因。

---

## 一、准备工作

### 1.1 安装运行环境

在宝塔「软件商店」安装以下组件：

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Nginx | 1.20+ | Web 服务器 |
| MySQL | 5.7 / 8.0 | 数据库 |
| PHP | **8.2 或 8.3** | 必须 8.2+，装低了会直接报错 |

> PHP 8.0 及以下无法运行本项目（Laravel 12 要求 PHP 8.2+）。

### 1.2 安装 PHP 扩展

宝塔「软件商店 → PHP 8.2 → 设置 → 安装扩展」，确认以下扩展已安装：

**必需**：`pdo_mysql`、`mbstring`、`openssl`、`fileinfo`、`ctype`、
`json`、`bcmath`、`tokenizer`、`xml`、`zip`、`curl`

**可选**：`gd`（Excel 导出插入图片时需要）、`intl`

其中 `pdo_mysql` 最关键 —— 没有它连不上数据库。

### 1.3 解除禁用函数

宝塔默认禁用了一些函数，本项目需要用到 `exec`。

进入「PHP 8.2 → 设置 → 禁用函数」，**删除**以下条目：

- `exec` —— 备份功能调用 mysqldump 与 openssl 需要
- `shell_exec` —— 用于探测 mysqldump 路径

> 如果暂时不需要自动备份功能，可以不解除，但备份任务会失败。

## 二、上传代码

### 2.1 上传

在宝塔「文件」中进入 `/www/wwwroot/`，新建目录 `cardkey`，
把项目文件上传进去。

推荐先在本地打包成 zip（排除 `node_modules`），上传后在宝塔里解压。

### 2.2 关于 vendor 与 public/build

**这两个目录已经在项目里准备好了**，可以直接上传：

- `vendor/`（约 150MB）—— Composer 依赖
- `public/build/` —— 前端构建产物

所以服务器上**不需要安装 Composer 和 Node.js**，省去很多麻烦。

> 如果上传太慢，也可以只传源码，然后在宝塔终端里执行
> `composer install --no-dev` 和 `npm run build`。
> 但要注意服务器需先装好 Composer 与 Node。

### 2.3 设置权限

在宝塔「文件」中右键 `cardkey` 目录 → 权限，设置为：

- 所有者：`www`
- 权限：`755`

然后单独给两个目录 `775` 权限：

```
/www/wwwroot/cardkey/storage
/www/wwwroot/cardkey/bootstrap/cache
```

或在终端执行：

```bash
chown -R www:www /www/wwwroot/cardkey
chmod -R 755 /www/wwwroot/cardkey
chmod -R 775 /www/wwwroot/cardkey/storage /www/wwwroot/cardkey/bootstrap/cache
```

## 三、创建站点

宝塔「网站 → 添加站点」：

| 字段 | 填写 |
| --- | --- |
| 域名 | 你的域名，如 `card.example.com` |
| 根目录 | `/www/wwwroot/cardkey/public` |
| FTP | 不创建 |
| 数据库 | 不创建（由安装向导自动建） |
| PHP 版本 | **8.2** |

### 关键：根目录必须指向 public

**这一步错了会导致严重的安全问题。**

如果根目录填 `/www/wwwroot/cardkey`（项目根），那么以下文件可以被
任何人直接下载：

- `.env` —— 含数据库密码和 APP_KEY
- `storage/logs/laravel.log` —— 含运行日志
- `composer.json`、`composer.lock`

填对 `public` 之后，这些文件在 Web 上不可访问。

**验证方法**：部署完成后访问 `https://你的域名/.env`，
应返回 404 或 403，**绝不能**下载到文件内容。

## 四、配置伪静态

宝塔站点「设置 → 伪静态」，粘贴：

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

不配置的话，除了首页以外所有页面都会 404。

### 4.1 补充 Livewire 规则（重要）

宝塔默认会在站点配置里加一条静态资源规则：

```nginx
location ~ .*\.(js|css)?$
{
    expires      12h;
}
```

Nginx 中 `location ~`（正则）优先级**高于** `location /`，因此所有 `.js` 请求
都会被它拦截并当作静态文件处理。但 **Livewire 的 JS 是 Laravel 动态生成的**
（路由 `/livewire-{hash}/livewire.min.js`，磁盘上不存在该文件），会被误判为
404 —— 结果是后台页面能打开，但**点击登录没反应**（Livewire 未加载）。

因此需要在站点配置文件 `/www/server/panel/vhost/nginx/你的域名.conf` 中，
**插入到静态资源规则之前**：

```nginx
# Livewire 的动态资源路由。
# 必须放在静态资源 location 之前：^~ 优先级高于正则匹配，
# 否则 /livewire-*/livewire.min.js 会被 js|css 规则拦截，导致 404。
location ^~ /livewire- {
    try_files $uri $uri/ /index.php?$query_string;
}
```

然后重载：

```bash
nginx -t && nginx -s reload
```

> **注意**：这一步不能写在宝塔的「伪静态」输入框里，因为伪静态文件只包含
> `location /` 块，无法控制与其他 `location` 的先后顺序。必须直接编辑站点配置文件。
>
> 另外检查宝塔生成的规则是否写成 `/index.php?query_string`（缺少 `$`）——
> 正确的是 **`$query_string`**。

完整的配置顺序参考：

```nginx
server {
    root /www/wwwroot/你的项目/public;

    location ^~ /livewire- {          # ← 必须在前
        try_files $uri $uri/ /index.php?$query_string;
    }

    location / {                       # ← 通用伪静态
        try_files $uri $uri/ /index.php?$query_string;
    }

    include enable-php-82.conf;

    location ~ .*\.(js|css)?$ { ... }  # ← 宝塔默认规则，保持在后
}
```

## 四之二、使用 Cloudflare 时的额外配置

如果你的域名接入 Cloudflare，有 **两项必须关闭**，否则后台无法登录：

| 设置项 | 位置 | 原因 |
| --- | --- | --- |
| **Rocket Loader** | 速度 → 优化 | 会改写 script 标签的 `type` 属性，导致 Livewire JS 不执行 |
| **Bot Fight Mode** | 安全性 → 机器人 | 注入 JS 质询脚本，阻塞后续脚本执行 |

这两项都与 Livewire 不兼容。Cloudflare 的其他功能（缓存、DDoS 防护、SSL）可以正常使用。

另外建议加一条缓存规则，让 Livewire 资源绕过 CDN 缓存：

```
缓存 → 缓存规则 → 创建规则
  当 URI 路径 包含 /livewire-
  则 绕过缓存
```

> 详细排查步骤见 [`故障排查-登录无反应.md`](./故障排查-登录无反应.md)。

## 五、运行安装向导

### 5.1 访问

浏览器打开：

```
http://你的域名/install.php
```

### 5.2 环境检查

页面顶部会显示环境检查结果。全部通过后才能点「开始安装」。

如果有不满足项，按提示处理：

| 提示 | 处理方法 |
| --- | --- |
| PHP 版本不满足 | 站点设置里换成 PHP 8.2 |
| 扩展未安装 | 宝塔 PHP 设置里安装对应扩展 |
| 目录不可写 | 按 2.3 节重设权限 |
| Composer 依赖缺失 | 说明 `vendor/` 没上传完整 |
| 前端资源缺失 | 说明 `public/build/` 没上传 |

### 5.3 填写配置

**数据库配置**：

| 字段 | 填写 |
| --- | --- |
| 数据库地址 | `127.0.0.1` |
| 端口 | `3306` |
| 数据库名 | `cardkey`（不存在会自动创建） |
| 用户名 | 建议在宝塔「数据库」里单独建一个用户 |
| 密码 | 对应用户的密码 |

> 不建议直接用 `root`。在宝塔「数据库 → 添加数据库」里创建一个
> 专用库和用户，权限更可控。

**管理员账号**：这是你登录后台用的账号，密码建议 12 位以上。

**站点信息**：

- 站点地址：填 `https://你的域名`（不要带末尾斜杠）
- 备份加密密码：**建议填写**，用于加密备份文件，丢失后备份无法解密

### 5.4 等待完成

点击「开始安装」后，向导会自动完成 10 个步骤：

```
数据库连接 → 创建数据库 → 写入 .env → 生成 APP_KEY
→ 引导框架 → 建表 → 创建管理员 → 初始化设置
→ 生成 install.lock → 缓存配置
```

完成后页面会显示成功，并列明已完成的操作。

## 六、安装后必做

### 6.1 删除安装文件（重要）

在宝塔文件管理里**删除 `public/install.php`**。

保留它意味着任何人都能重置你的数据库。

同时确认根目录生成了 `install.lock`（防止重复安装）。

### 6.2 备份 .env

把 `.env` 下载到本地保存。

**特别是 `APP_KEY`** —— 它用于加密卡密明文和 AppSecret。
一旦丢失或更换，已加密的数据将**永久无法恢复**，API 会全部验签失败。

### 6.3 配置定时任务

宝塔「计划任务 → 添加任务」：

| 字段 | 填写 |
| --- | --- |
| 任务类型 | Shell 脚本 |
| 任务名称 | 卡密系统调度 |
| 执行周期 | **N 分钟 → 1 分钟** |
| 脚本内容 | 见下 |

```bash
cd /www/wwwroot/cardkey && php artisan schedule:run >> /dev/null 2>&1
```

> 注意：脚本里的 `php` 需是 8.2 版本。如果系统默认 PHP 是其他版本，
> 写完整路径，例如 `/www/server/php/82/bin/php`。

不配置这个，以下功能都不会工作：

- 日志自动清理（每天 03:00）
- nonce 防重放记录清理（每 30 分钟）
- 卡密到期/用完状态同步（每 15 分钟）
- 数据库自动备份（每天 04:00）

### 6.4 配置队列进程（建议）

宝塔「软件商店 → 进程守护管理器 → 添加进程」：

| 字段 | 填写 |
| --- | --- |
| 名称 | cardkey-queue |
| 启动用户 | www |
| 运行目录 | `/www/wwwroot/cardkey` |
| 启动命令 | `/www/server/php/82/bin/php artisan queue:work --sleep=3 --tries=3` |

### 6.5 开启 HTTPS

宝塔站点「SSL」：

1. 申请 Let's Encrypt 免费证书（或上传自己的证书）
2. 开启「强制 HTTPS」

客户端走 HTTP 会带来中间人篡改风险，生产环境必须用 HTTPS。

### 6.6 验证部署

在浏览器依次确认：

| 检查项 | 预期结果 |
| --- | --- |
| `https://域名/admin` | 显示登录页 |
| `https://域名/.env` | 404 或 403 |
| `https://域名/install.php` | 404（已删除） |
| 用管理员账号登录后台 | 能进入 |

## 七、登录后台后的配置

### 7.1 创建应用

「应用管理 → 新建应用」，填写名称后保存。

**立刻保存生成的 AppID 与 AppSecret** —— 用于客户端对接。

AppSecret 只在创建时完整显示一次（之后可在后台「查看密钥」中查看，
需二次输入管理员密码）。

### 7.2 配置安全参数

在应用编辑页配置：

| 参数 | 建议值 | 说明 |
| --- | --- | --- |
| 强制卡密密文传输 | 开启 | 客户端必须加密提交卡密 |
| 每分钟请求上限 | 60~300 | 按业务量调整 |
| 每日调用配额 | 按需 | 0 表示不限，建议设上限 |
| IP 白名单 | 有固定出口 IP 时填写 | 留空表示不限制 |

### 7.3 生成卡密

「卡密管理 → 批量生成卡密」，选择类型与数量。

支持四种类型：时间卡、次数卡、永久卡、试用卡。

### 7.4 系统设置

「系统设置」里建议开启：

- 强制卡密密文传输
- 响应体附带签名

> 注意：设置项中的「强制 HTTPS」「会话空闲超时」「登录失败锁定」
> 在当前版本**尚未接线到运行时代码**，不要依赖它们做安全加固。
> HTTPS 请在宝塔层面配置。

## 八、日常维护

### 8.1 修改代码后

```bash
cd /www/wwwroot/cardkey
php artisan optimize:clear
php artisan optimize
```

否则可能读到旧缓存。

### 8.2 手动备份

```bash
cd /www/wwwroot/cardkey
php artisan cardkey:backup
```

备份文件位于 `storage/app/private/backups/`，格式为
`cardkey_backup_日期_时间.sql.enc`。

**备份文件是用 `BACKUP_ENCRYPTION_PASSWORD` 加密的**，恢复时需要该密码：

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 \
  -in cardkey_backup_xxx.sql.enc -out restore.sql \
  -pass pass:'你的备份密码'

mysql -u 用户名 -p 数据库名 < restore.sql
```

### 8.3 查看日志

- 应用日志：`storage/logs/laravel.log`
- 安装异常：`storage/logs/install-error.log`

### 8.4 如果 mysqldump 找不到

备份命令会自动探测常见路径（含宝塔的 `/www/server/mysql*/bin/`）。

如果仍提示找不到，在 `.env` 中显式指定：

```ini
BACKUP_MYSQLDUMP_PATH=/www/server/mysql/bin/mysqldump
```

## 九、常见问题

### 访问站点显示 500 错误

1. 检查站点根目录是否为 `public`
2. 检查 `storage` 与 `bootstrap/cache` 权限（775，属主 www）
3. 查看 `storage/logs/laravel.log` 最后几行

### 后台样式错乱

`public/build/` 未上传或未构建。该目录已随仓库提供，确认上传完整即可。

### npm run build 报 Node 版本错误

```
You are using Node.js 18.19.1. Vite requires Node.js version 20.19+ or 22.12+.
```

**先确认是否真的需要构建**：`public/build/` 已随仓库提供，
除非你改过 `resources/` 下的前端源码，否则**跳过这一步**。

确实需要构建时，用宝塔的 Node 版本管理器装新版：

```bash
# 宝塔「软件商店 → Node.js 版本管理器」安装 Node 20 或 22
# 然后切换到该版本
bt-node --set-default 20

# 清理后重新安装
rm -rf node_modules package-lock.json
npm install
npm run build
```

### npm 报 Cannot find native binding

```
Error: Cannot find native binding. npm has a bug related to optional dependencies
```

这是 npm 处理可选依赖的已知问题，通常是 `node_modules` 与 `package-lock.json`
不一致导致。清理后重装即可：

```bash
rm -rf node_modules package-lock.json
npm install
```

如果仍失败，且 Node 版本已达标，可以改用 pnpm 或 yarn：

```bash
npm install -g pnpm
pnpm install
pnpm run build
```

### 提示 "could not find driver"

PHP 缺少 `pdo_mysql` 扩展。宝塔 PHP 设置里安装。

### 安装向导显示"环境检查未通过"但看不出原因

页面会列出每一项的具体状态与要求，对照第五节的表格处理。

### 忘记管理员密码

在宝塔终端执行：

```bash
cd /www/wwwroot/cardkey
php artisan tinker --execute="App\Models\User::first()->update(['password' => bcrypt('新密码')]);"
```

### 需要重新安装

1. 删除根目录的 `install.lock`
2. 删除数据库中的所有表（或直接删库）
3. 重新访问 `/install.php`

> 注意：重新安装会生成新的 `APP_KEY`，
> **原有的卡密密文与 AppSecret 将无法解密**。

## 十、安全清单

部署完成后逐项确认：

- [ ] 站点根目录指向 `public/`
- [ ] `public/install.php` 已删除
- [ ] 访问 `/.env` 返回 404
- [ ] `.env` 已备份到本地
- [ ] `APP_DEBUG=false`
- [ ] 已开启 HTTPS 并强制跳转
- [ ] 数据库使用专用账号（非 root）
- [ ] 定时任务已配置（每分钟）
- [ ] 备份功能测试通过
- [ ] 每个应用都配置了每日配额
- [ ] 管理员密码足够复杂
